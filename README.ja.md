# ComfyUI-MiRipple（非公式）— 概要

[Mi-Ripple](https://github.com/miyang-ai/Mi-Ripple)（MIT）のうち、ローカルで決定的に動く部分を ComfyUI の
2 ノードとして使えるようにしたものです。CPU のみで動作し、モデルの重みやネットワークは使いません。
詳細と検証結果は [README.md](README.md)（英語）にあります。

- **非公式**: MIYANG Technology (Shanghai) Co., Ltd. および Mi-Ripple 作者とは無関係で、承認も受けていません。
- **ローカル専用**: MIYANG の再生成 API は呼びません。`MIYANG_*` 環境変数は無視され、画像は外部へ送られません。
- **万能クリーナーではありません**: 対象は周期格子と平坦部の粒状アーティファクトだけです。公式結果が「検証済みの納品」でないときは、入力をそのまま返し、理由をレポートに書きます。

## ノード

- **Mi-Ripple Diagnose**: 公式の診断を実行します。出力はスケールヒートマップ、診断ボード、マスク 2 種、格子検出フラグ、レポートです。画像は変更しません。
- **Mi-Ripple Local Repair**: 公式の処理順（diagnose → notch / iso_clean → verify）で修復します。出力は次のとおりです。
  - `image`: `restoration_applied` が true のときだけ修復候補、それ以外は入力そのもの
  - `candidate`: 公式の修復候補（検証に失敗した場合も含む）
  - `change_mask`, `restoration_applied`
  - `outcome`: 公式の outcome をそのまま
  - `report`

`delivered_with_verify_failure` は、既定では入力を返します（`accept_verify_failure` を on にすると候補を返します）。
`needs_human_decision` / `failed` / `step_limit` も入力を返します。キャンセル時は ComfyUI の中断として扱います。

## 検証の要点（Windows 11 1 台、CPU）

- **比較対象**: 未改変の公式パッケージ（commit `865a148…`）。同じライブラリ版で、OpenCV なしの環境です。
- **入力 19 件**: 512×512 の主要 12 件、上流の合成画像、640×480、上流テスト用の 384×512。
- **一致の範囲**: 次の 3 経路すべてで、19 件とも全層（入力、outcome、診断・検証 JSON、全中間画像、ノード出力）が完全一致しました。
  - ノードランタイムの直接実行
  - 実際の ComfyUI v0.38.0 キュー
  - 別名フォルダへのクリーンインストール
- **結果**: 512×512 の格子ケースはどれも公式の検証を通らず、ノードは入力を返しました。検証を通った納品は、上流の 384×512 テスト画像（検証済みサイズの範囲外）だけです。正当な繰り返し模様では、候補が模様を壊す例（レンガ目地）を公式の検証が却下しました。
- **中断**: 即時ではありません。上流の処理ステップ単位で止まります。
  - 512×512: `/interrupt` から 90〜737 ms（開発環境とクリーンインストールで計 10 回）
  - 1536×1536: 0.3〜6.7 s（計 8 回）
- **OpenCV**: 「import できるが使えない」OpenCV で上流が `failed` になる問題（Issue #1）に、ローカルパッチを 1 つ当てています。同じ内容を上流に PR #2 として提案済みです。

## 制限

- 検証済みの範囲は 512×512 RGB、バッチ 1 です。それ以外のサイズは `any size (unverified)` を選んだときだけ処理します。バッチ入力や RGB 以外の入力は拒否します。黙ってリサイズ・切り抜き・破棄することはありません。
- 入力は公式の PNG 入力と同じく 8 bit に丸めます。
- ライブラリの版によって数値が変わる可能性があります。使用した版はレポートに記録されます。
